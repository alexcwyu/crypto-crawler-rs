Purpose and scope

Collects public crypto exchange streams and REST snapshots into timestamped raw-message envelopes; a data acquisition workspace rather than a strategy or matching engine.

Design decisions

Decision Rationale Tradeoff Evidence
Preserve raw exchange JSON in a uniform metadata envelope. Retains source payload and local receipt time for downstream consumers. Consumer must normalize message schemas and provide durable storage. Message (L12)
Discover subscriptions and enforce venue-specific request cooldowns. Limits overloaded connections and REST rate contention across processes. Venue maps/cooldowns age; configured entries are not live availability guarantees. crawl_event (L705) / fetch_symbols_retry (L15) / get_market_types (L53)

Strengths and limits

Strengths

  • REST snapshots terminate when the output receiver disappears and metadata retries are bounded. crawl_snapshot (L106) / fetch_symbols_retry (L15)

Limitations

  • No algorithm execution, portfolio or order-management flow was established; the source is a market-data acquisition layer. crawl_trade (L223) / Message (L12)
  • Retired venue routes and live authentication/arrival failures remain visible; current test exclusions must not imply all feeds work. docs/validation.md (L16) / get_market_types (L53)

Validation scope

The linked validation and command records preserve actual historical runs and user-authorized exclusions. This source/document review does not rerun application tests, establish live trading readiness or rank benchmark performance. Current data, credential and runtime prerequisites remain material.
